# Практическая работа №5

## Тема
Разработка отдельных модулей внедряемого программного обеспечения и их объединение в одно приложение.

## Выбранный вариант
Система регистрации обращений пользователей.

## Цель работы
Нужно разбить систему на отдельные части, понять за что отвечает каждая часть и показать, как они будут работать вместе.

## Основные модули

### 1. Модуль авторизации
Нужен для входа пользователей в систему.

Что делает:
- проверяет логин и пароль;
- определяет пользователя;
- не дает обычному пользователю выполнять действия администратора.

### 2. Модуль обращений
Это основной модуль системы.

Что делает:
- создает новое обращение;
- хранит тему и описание проблемы;
- хранит дату создания;
- показывает текущий статус;
- позволяет изменить обращение.

Статусы можно сделать простыми: новое, в работе, выполнено, закрыто.

### 3. Модуль исполнителей
Нужен для назначения сотрудника на обращение.

Что делает:
- хранит список исполнителей;
- назначает исполнителя на заявку;
- показывает, какие заявки уже находятся у сотрудника в работе.

### 4. Модуль уведомлений
Нужен для сообщения пользователю об изменениях.

Например, уведомление отправляется, когда:
- обращение создано;
- назначен исполнитель;
- изменился статус;
- обращение закрыто.

### 5. Модуль отчетов
Нужен для простой статистики по обращениям.

Можно показать:
- сколько всего обращений;
- сколько новых;
- сколько находится в работе;
- сколько выполнено;
- сколько заявок у каждого исполнителя.

## Как модули связаны между собой

```text
Пользователь
    |
    v
Интерфейс
    |
    v
Авторизация
    |
    v
Модуль обращений <----> База данных
    |
    +----> Модуль исполнителей
    |
    +----> Модуль уведомлений
    |
    +----> Модуль отчетов
```

Все модули работают с общими данными. Например, после создания обращения оно сохраняется в базе. Потом к нему можно назначить исполнителя. После изменения статуса модуль уведомлений сообщает об этом пользователю, а модуль отчетов учитывает изменение в статистике.

## Пример работы системы

1. Пользователь входит в систему.
2. Создает обращение и описывает проблему.
3. Обращение получает статус «Новое».
4. Сотрудник назначает исполнителя.
5. Статус меняется на «В работе».
6. После выполнения задачи ставится статус «Выполнено».
7. Пользователь получает уведомление.
8. Информация попадает в общую статистику.

## Проверка совместной работы

Для проверки можно выполнить несколько обычных действий:

- войти в систему;
- создать обращение;
- назначить исполнителя;
- поменять статус обращения;
- проверить появление уведомления;
- открыть отчет и проверить, что количество обращений изменилось.

Если данные после каждого действия сохраняются и остальные модули видят изменения, значит модули связаны правильно.

## Результат

В итоге получается приложение, состоящее из нескольких простых модулей. Каждый модуль отвечает за свою задачу, но все они работают с общей системой обращений.
