### Проектирование внедряемого программного обеспечения

**Вариант:** Электронный журнал группы

---

## Шаг 1. Постановка задачи

**Объект проектирования:** электронный журнал группы.

**Круг пользователей системы:**
- преподаватели;
- студенты;
- куратор группы;
- администратор.

**Исходные проблемы:**
- оценки и посещаемость приходится записывать вручную;
- данные могут потеряться или быть записаны с ошибкой;
- сложно быстро посмотреть успеваемость и пропуски;
- на подготовку отчётов уходит лишнее время.

**Основные функции системы:**
- вход в систему по логину и паролю;
- просмотр списка студентов;
- выставление и изменение оценок;
- отметка посещаемости;
- просмотр оценок и пропусков;
- подсчёт среднего балла;
- формирование простых отчётов.

**Ограничения и требования:**
- система должна быть простой в использовании;
- должна работать на компьютерах учебного заведения;
- нужен доступ к интернету;
- доступ к функциям зависит от роли пользователя.

**Ожидаемый результат:**
- более быстрый учёт оценок и посещаемости;
- меньше ошибок при ведении журнала;
- преподаватели и студенты смогут быстро получать нужную информацию.

---

## Шаг 2. Выбор платформы реализации

Рассмотрены три варианта:

| Платформа | Плюсы | Минусы |
|---|---|---|
| Веб-платформа | Работает через браузер, не нужно ставить программу на каждый компьютер, удобно обновлять | Нужен интернет |
| Настольное приложение | Может работать локально, привычный формат программы | Нужно устанавливать и обновлять на каждом компьютере |
| Мобильное приложение | Удобно пользоваться с телефона | Нужно отдельно разрабатывать и устанавливать приложение |

**Выбранный вариант:** веб-платформа.

**Почему выбрана веб-платформа:**
- можно открыть журнал с любого компьютера через браузер;
- не нужно устанавливать программу на каждое рабочее место;
- обновление системы выполняется централизованно;
- подходит для преподавателей и студентов.

---

## Шаг 3. Проектирование компонентов внедряемого ПО

**Основные компоненты системы:**
- пользовательский интерфейс;
- модуль авторизации;
- модуль электронного журнала;
- модуль посещаемости;
- база данных;
- модуль отчётов;
- панель администратора.

### Схема компонентов

```text
Пользователь
    ↓
Веб-интерфейс
    ↓
Сервер приложения
    ├── База данных
    ├── Модуль электронного журнала
    ├── Модуль посещаемости
    ├── Модуль отчётов
    └── Панель администратора
```

**Назначение компонентов:**

| Компонент | Назначение |
|---|---|
| Веб-интерфейс | Работа пользователя с системой через браузер |
| Авторизация | Вход в систему и проверка роли пользователя |
| Электронный журнал | Выставление и просмотр оценок |
| Посещаемость | Учёт пропусков студентов |
| База данных | Хранение пользователей, оценок и посещаемости |
| Отчёты | Просмотр среднего балла и общей успеваемости |
| Панель администратора | Добавление пользователей, групп и настройка системы |

## Шаг 4. Оценка сроков выполнения работ

При оценке сроков учитываются:
- объём и сложность работ;
- количество исполнителей;
- необходимость тестирования;
- время на обучение пользователей;
- небольшой резерв времени.

### Календарный план

| Этап работ | Длительность | Рабочие дни |
|---|---:|---|
| Анализ требований | 2 дня | 1–2 |
| Выбор платформы | 2 дня | 3–4 |

| Тестирование | 3 дня | 10–12 |

**Итого: 15 рабочих дней.**
